# PETCH

반려동물과 함께 갈 수 있는 식당·카페를 찾는 정적 웹앱입니다. `index.html` 하나로 동작하며 Netlify에 그대로 배포할 수 있습니다.

## 이번 버전의 권한

| 사용자 | 조회 | 추천·비추천 | 정보 수정 | 가게 추가 |
|---|---:|---:|---:|---:|
| 비회원 | 가능 | 불가 | 불가 | 불가 |
| 일반 회원 | 가능 | 가능 | 불가 | 불가 |
| 관리자 | 가능 | 가능 | 가능 | 가능 |

- 로그인은 Supabase Auth의 이메일·비밀번호 방식을 사용합니다. 데모 화면에는 회원가입 기능을 노출하지 않습니다.
- 일반 회원은 가게별로 추천 또는 비추천을 한 번 선택하고, 나중에 선택을 바꿀 수 있습니다.
- 관리자가 추가하거나 수정한 가게는 자동으로 `PETCH 인증` 상태가 됩니다.
- 관리자는 위도·경도를 직접 입력하지 않고 도로명 주소를 검색해 위치를 설정합니다. 주소 검색 성공 시 시/도·시/군/구·읍/면/동과 좌표가 자동 입력됩니다.
- 관리자는 매장 내 이동 조건을 `확인 전`, `이동장 필수`, `매장 내 보행 가능` 중 하나로 기록할 수 있습니다. 확인된 조건은 검색 결과 카드에 태그로 표시됩니다.
- 인증되지 않은 기본 목록에는 회색 `공공데이터` 표시가 붙습니다.
- 검색 조건의 `PETCH 인증 가게만`을 켜면 관리자가 확인한 가게만 볼 수 있습니다.
- 권한은 화면을 숨기는 데 그치지 않고 Supabase RLS와 RPC에서도 검사합니다.

## 파일

- `index.html`: 배포할 웹앱
- `supabase_setup.sql`: 인증·권한·가게·투표 테이블과 정책을 만드는 SQL

## 처음 설정하는 순서

### 1. Supabase SQL 실행

Supabase Dashboard → SQL Editor에서 `supabase_setup.sql` 전체를 한 번 실행합니다.

이 SQL은 다음을 만듭니다.

- `profiles`: 회원 역할(`member` 또는 `admin`)
- `places`: 관리자가 직접 추가하거나 확인한 가게 정보
- `member_place_votes`: 회원별 추천·비추천
- `get_place_votes`, `cast_place_vote`: 투표 조회·저장 RPC
- 회원 가입 시 기본 `member` 프로필을 만드는 트리거
- 비회원 쓰기 차단, 회원 투표 허용, 관리자 가게 관리 허용 RLS 정책

기존의 공개 쓰기용 `place_tags`, `place_votes` 테이블이 있다면 행을 삭제하지 않고 새 쓰기만 차단합니다. 새 기능은 별도 `member_place_votes` 테이블을 사용합니다.

### 2. 데모 계정 생성과 관리자 지정

Supabase Dashboard → Authentication → Users에서 `Add user`로 테스트용 일반회원과 관리자 계정을 직접 생성합니다. 공개 회원가입은 Authentication 설정에서 비활성화해 둡니다.

관리자 계정을 만든 다음 SQL Editor에서 아래 쿼리를 실행합니다. 이메일은 실제 관리자 계정으로 바꾸세요.

```sql
update public.profiles p
set role = 'admin'
from auth.users u
where p.id = u.id
  and u.email = 'admin@example.com';
```

해당 계정으로 로그인하면 헤더에 `가게 추가` 버튼이 나타납니다. 일반회원 테스트 계정은 `member` 역할을 그대로 유지합니다.

### 3. Netlify 재배포

수정된 `index.html`을 기존 Netlify 사이트에 배포합니다. 현재 Supabase 프로젝트 URL과 publishable key는 브라우저용 공개 키이므로 HTML에 있어도 됩니다. `service_role` 키는 절대 HTML이나 저장소에 넣지 마세요.

### 4. 카카오 지도 도메인 등록

Kakao Developers → 내 애플리케이션 → 플랫폼 → Web에서 실제 Netlify 도메인을 등록합니다. 등록하지 않으면 검색은 동작하지만 실제 지도 대신 예시 지도가 보일 수 있습니다.

## 데이터 운영 원칙

- 기본 목록은 식품안전나라 등 공개 출처 데이터를 사용하고 회색 `공공데이터`로 표시합니다.
- 관리자가 전화 확인, 공식 채널 확인, 현장 확인 등으로 정보를 보강한 뒤 저장하면 `PETCH 인증`으로 전환됩니다.
- 인증 메모에는 확인 수단과 근거를 짧게 남기는 것이 좋습니다. 예: `2026-09-11 전화 확인, 실내 소형견 가능`.
- 단순히 웹 페이지를 긁었다는 이유만으로 인증하지 말고, 최신성·가게 식별·동반 조건을 확인한 경우에만 인증합니다.
- 추천 수는 인기 신호일 뿐 사실 확인 근거로 사용하지 않습니다.

## 현재 데이터와 한계

- 기본 업소 목록은 `index.html`에 정적으로 포함되어 있고, 관리자 추가·수정분만 Supabase `places`에서 덮어씁니다.
- 주소·전화번호·메뉴·편의시설은 원본 출처에 따라 비어 있거나 실제와 다를 수 있습니다.
- 거리 표시는 사용자가 위치 권한을 허용한 `내 위치 주변` 검색에서만 계산합니다.
- 즐겨찾기는 아직 브라우저 `localStorage`에 저장되므로 다른 기기와 동기화되지 않습니다.

## 운영 안정성

- 투표는 사용자당 가게별 한 행만 유지되고 계정당 신규 가게 투표를 500개로 제한해 중복 클릭이나 단일 계정 남용으로 행이 무한히 늘지 않습니다.
- 결과 목록은 여러 가게의 투표 수를 RPC 한 번으로 묶어 조회합니다.
- 관리자 쓰기는 RLS로 제한되며, 브라우저에 관리자 비밀키를 두지 않습니다.
- 다만 현재 가게 기본 데이터가 정적이고 전체 결과가 한 번에 렌더링되므로, 데이터가 수천~수만 곳으로 늘면 `places`를 완전히 DB로 이전하고 서버측 검색·페이지네이션을 추가해야 합니다.

## 배포 전 확인

1. 비회원에게 추천·비추천 및 수정 버튼이 보이지 않는지 확인
2. 일반 회원에게 추천·비추천만 보이는지 확인
3. 관리자에게 `가게 추가`, `정보 확인·수정`이 보이는지 확인
4. 관리자 저장 후 초록색 `PETCH 인증`과 확인일이 표시되는지 확인
5. 신규 가게에서 주소 검색 전에는 저장되지 않고, 검색 성공 후 위치가 지도에 정상 표시되는지 확인
6. `PETCH 인증 가게만` 필터가 동작하는지 확인
7. Supabase Table Editor에서 비회원 공개 쓰기 정책이 없는지 확인
